## 新增需求

### 需求：文档身份系统必须通过 frontmatter 为每个 Markdown 文档分配稳定的唯一 ID
系统必须为工作区中每个 `.md` 文档在 YAML frontmatter 中分配不可变的 `jarvis_id`。ID 必须为 ULID 字符串，使用 `jarvis_id` 前缀以避免与其他工具冲突。ID 必须在首次关联时（对话或任务首次链接到该文档时）分配。非 markdown 文件和目录不得接收 frontmatter ID。

#### 场景：首次关联时分配 ID
- **当** 某对话或任务首次链接到某 `.md` 文档
- **且** 该文档的 frontmatter 中尚未包含 `jarvis_id` 字段
- **则** 系统必须生成新的 ULID 并将其作为 `jarvis_id` 写入文档的 YAML frontmatter
- **且** 文档正文内容必须保持不变

#### 场景：后续关联时保留已有 ID
- **当** 某对话或任务链接到某 `.md` 文档
- **且** 该文档的 frontmatter 中已包含有效的 `jarvis_id`
- **则** 系统必须使用现有的 `jarvis_id`，不修改文件

#### 场景：写入 ID 时保留用户编写的 frontmatter
- **当** 系统向已有其他 frontmatter 字段的文档写入 `jarvis_id`
- **则** 所有现有 frontmatter 字段必须以原始值保留
- **且** `jarvis_id` 字段必须追加，不得改变现有字段的顺序、注释或格式

#### 场景：非 markdown 文件不接收 ID
- **当** 用户尝试将非 markdown 文件（如 `.pdf`、`.png`）链接到对话或任务
- **则** 系统不得尝试向该文件写入 `jarvis_id`
- **且** 系统必须优雅处理此情况（如拒绝链接或仅存储路径引用）

---

### 需求：DocumentIdentityIndex 必须在工作区初始化时从 frontmatter 构建
系统必须在初始化时扫描工作区中所有 `.md` 文件，并构建将 `jarvis_id → 当前虚拟路径` 的内存 `DocumentIdentityIndex`。所有 ID 到路径的解析和路径到 ID 的查找必须使用该索引。不需要持久化索引文件。

#### 场景：工作区初始化时构建索引
- **当** 工作区上下文 provider 初始化访问
- **则** 系统必须扫描工作区中所有 `.md` 文件
- **且** 对包含 `jarvis_id` frontmatter 字段的每个文件，必须向索引添加 `id → 路径` 条目
- **且** 索引必须在任何文档被打开之前可用于查找

#### 场景：将 ID 解析为当前路径
- **当** 系统被要求将 `jarvis_id` 解析为文档路径
- **且** 该 ID 存在于索引中
- **则** 系统必须返回该文档的当前虚拟路径
- **且** 解析必须在不进行任何文件系统访问的情况下完成

#### 场景：对未知 ID 返回 null
- **当** 系统被要求解析不在索引中的 `jarvis_id`
- **则** 系统必须返回 `null`（将该文档视为已删除或尚未索引）

#### 场景：高效批量解析多个 ID
- **当** 系统被要求在一次调用中解析多个 `jarvis_id` 值
- **则** 系统必须为所有请求的 ID 返回 `id → ContextNode | null` 的映射
- **且** 不得为每个 ID 单独执行文件系统扫描

---

### 需求：DocumentIdentityIndex 必须在文档于 agent 内改名或移动时原地更新
系统必须将 `DocumentIdentityIndex` 的更新作为任何 `renameNode` 或 `moveNode` 操作的一部分。存储在 frontmatter 中的 ID 必须保持不变。当文档在其 agent 内移动时，无需重写任何关系数据（对话、任务）。

#### 场景：改名后更新索引
- **当** 用户在其 agent 内重命名某 `.md` 文档
- **则** 系统必须更新该文档 `jarvis_id` 的索引条目以反映新路径
- **且** 文档 frontmatter 中的 `jarvis_id` 不得改变
- **且** 通过该 `jarvis_id` 链接的所有对话或任务必须继续解析到正确的（新）文档路径

#### 场景：agent 内移动后更新索引
- **当** 用户将某 `.md` 文档移动到同一 agent 内的不同目录
- **则** 系统必须将索引条目更新为新的虚拟路径
- **且** 已链接的对话和任务必须继续正确解析

#### 场景：目录改名时更新所有文档的索引
- **当** 用户重命名包含多个 `.md` 文档的目录
- **则** 系统必须将所有受影响文档的索引条目更新为新路径
- **且** 所有已链接的对话和任务必须在目录改名后正确解析

---

### 需求：DocumentIdentityIndex 必须检测并解决重复 ID
系统必须检测两个 `.md` 文件包含相同 `jarvis_id` 的情况（如外部 `cp` 操作后），并在初始化时通过为修改时间较新的文件重新分配新 ULID 来解决冲突。

#### 场景：初始化时检测重复 ID
- **当** 工作区初始化时，两个或更多 `.md` 文件包含相同的 `jarvis_id`
- **则** 系统必须检测到冲突
- **且** 必须记录警告，标识冲突文件

#### 场景：通过为较新文件重新分配 ID 来解决重复
- **当** 检测到重复的 `jarvis_id`
- **则** 系统必须为 `mtime` 较新的文件分配新的 ULID
- **且** 必须将新的 `jarvis_id` 写入该文件的 frontmatter
- **且** 原始文件必须保留其原始 `jarvis_id`
