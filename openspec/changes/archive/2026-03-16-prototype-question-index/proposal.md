## Why

当前 ChatPrism 已具备共享聊天工作台、多模态输入和本地/外部历史能力，但长对话仍缺少“对话内问题级索引”。用户只能在主线程里线性滚动查找历史问题，无法快速定位关键问答、标记重点内容或在本地隐藏无关问答后继续整理当前线程；同时当前输入框仍采用 Enter 直接发送，停止生成后也不会把刚才的提示词回填，和桌面端生产力工具的预期不一致。

左侧本地历史列表目前也缺少会话级删除入口。测试会话、失败分支和临时对话会持续堆积，用户既不能在侧边栏直接清理，也无法把删除动作同步到服务器侧，导致跨端恢复后旧会话又重新出现。

`phase-10.md` 希望把“操作收敛在右侧面板”的长对话管理模式落到现有工作台中，让问答索引、星标、软删除、滚动定位和输入恢复成为统一的一组能力。这一阶段的重点是在现有聊天体验之上补齐长会话的信息组织与编辑效率。

## What Changes

- 新增右侧问题索引面板，仅展示当前会话中用户提问的第一行（超出部分不显示），并支持“全部 / 仅看星标”筛选。
- 在问题条目上提供悬停操作：星标收藏与内联删除确认；删除后主视图中的对应问答对同步淡出并从本地可见线程中过滤。
- 为问答对引入可持久化的星标与软删除元数据，使状态在刷新、恢复与同步后保持一致，并为后续“撤销删除”留下空间。
- 在左侧本地历史条目上提供仅在 hover 时显示的“删除”按钮；用户确认后，系统对整条会话执行硬删除，并将该删除同步到服务器侧会话记录。
- 在主聊天视图中补充 ScrollSpy 与锚点滚动联动：滚动历史时右侧索引自动高亮当前视口问题；点击索引项时主视图平滑滚动到对应问答对。
- 调整输入区交互为 `Enter` 换行、`Ctrl+Enter` / `Cmd+Enter` 发送，并提供显式快捷键提示。
- 当助手流式回复进行中时，发送按钮切换为“停止”；用户停止生成后，系统恢复刚刚发送的提示词到输入框并自动聚焦，便于继续修改后重发。

## Capabilities

### New Capabilities

- `question-index-panel`: 为单个会话提供右侧问题级索引、星标筛选、内联删除确认、滚动定位和视口高亮能力。

### Modified Capabilities

- `conversation-workspace`: 在现有共享聊天工作台中接入右侧问题索引面板、主线程与索引联动、左侧本地历史 hover 删除入口、桌面端输入快捷键规范以及停止生成后的草稿回填。
- `core-interfaces`: 扩展 `ConversationMessage` 或等价核心消息结构，支持问题分组标识、时间戳、星标状态和软删除状态，以表达问答对级别的管理语义。
- `storage-provider`: 持久化层在保存、读取和恢复会话时保留问题索引相关元数据，并在用户删除左侧历史项时对整条会话执行硬删除。
- `sync-storage-provider`: Local-First 同步链路在 push / pull / hydrate 后继续保留消息级星标、软删除和问题分组字段，同时需要把左侧整会话删除作为跨端可传播的硬删除事件处理。
- `sync-server`: 服务端同步能力需要支持接收整会话硬删除并物理移除对应记录，同时继续向其他客户端广播删除结果，避免被后续 pull 回流。

## Impact

- 受影响代码主要位于 `packages/ui/src/views`、`packages/ui/src/components`、`packages/ui/src/store/chat.ts`、`packages/core/src/interfaces`、`packages/core/src/providers`、`apps/web/src`、`apps/extension/src`、`apps/server/src/routes`、`apps/server/src/services`、`apps/server/src/repositories` 与 `apps/server/src/types/sync.ts`。
- 需要补充共享 UI 单测、chat store 单测、同步层单测、服务端同步测试、Web E2E，以及在需要覆盖扩展场景时补充扩展宿主 E2E；扩展 E2E 需按项目约定申请提权并使用 `channel: 'chromium'`。
- 该变更以兼容方式扩展消息模型，不要求立即迁移旧会话；旧数据可以在缺失新增字段时按默认未星标、未删除处理。
- 对于依赖远端会话 ID 续聊的 provider，本阶段软删除仅影响本地 UI、索引与持久化结果，不回写或重建既有远端会话上下文。
- 左侧历史项删除与问答对软删除是两条独立语义：问答对继续使用消息级软删除；整条会话删除采用本地与服务端一致的硬删除，不提供回收站。
