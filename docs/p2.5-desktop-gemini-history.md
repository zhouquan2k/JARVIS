# Desktop Gemini 历史导入 + Core 目录收口重构

## 摘要

- 本次变更合并两类工作：
  1. 在 `desktop` 实现 `gemini-web` 历史对话导入，替换当前 `Desktop Gemini history provider is not implemented yet`
  2. 对 `packages/core/src` 做一次结构化收口，把 `providers`、`agents`、`runtime`、`analysis/workflows` 调整到更清晰的边界
- 登录恢复采用已确认方案：桌面端提供与 ChatGPT 一致风格的 `登录 Gemini` 按钮，不做自动弹窗。
- 重构范围以“目录与依赖边界收口”为主，不改变现有接口语义与对外能力。

## Desktop Gemini 历史导入实现

### 5. 共享 Gemini history 内核

共享实现放在 `packages/core/src/providers/history/gemini/`：

- `interface GeminiHistoryBridge`
  - `getHistoryList(config: GeminiHistoryRemoteConfig): Promise<GeminiContentHistorySummary[]>`
  - `getHistoryDetail(config: GeminiHistoryRemoteConfig, externalId: string): Promise<GeminiContentConversationDetail>`
- `class GeminiHistoryConfigLoader`
  - `constructor(options: { storage: ConfigStorage; env?: Record<string, string | undefined>; fetchImpl?: typeof fetch; now?: () => number; builtinConfig?: GeminiHistoryRemoteConfig })`
  - `load(): Promise<ProviderRemoteConfigLoadResult<GeminiHistoryRemoteConfig>>`
  - `markValidated(config: GeminiHistoryRemoteConfig): Promise<void>`
- `class GeminiDomHistoryProvider implements IHistoryProvider`
  - `getHistoryList(): Promise<ConversationHistorySummary[]>`
  - `getHistoryDetail(externalId: string): Promise<Conversation>`

保留行为：

- 远程配置、缓存回退、builtin 回退逻辑不变
- 继续使用现有错误码：
  - `AUTH_REQUIRED`
  - `CONFIG_UNAVAILABLE`
  - `SELECTOR_MISMATCH`
  - `DETAIL_NOT_FOUND`
  - `TAB_UNAVAILABLE`

### 6. desktop 主进程 bridge

新增：

- `apps/desktop/main/GeminiHistoryPageBridge.ts`
- `apps/desktop/main/gemini-history.preload.ts`

实现：

- `GeminiHistoryPageBridge implements GeminiHistoryBridge`
- 通过隐藏受控窗口加载 Gemini 页面
- 通过专用 preload 向页面注入桥，调用共享 DOM 抽取逻辑
- 支持：
  - 历史列表抓取
  - 指定 externalId 的详情抓取
  - 登录页/错误页识别并映射为 `ExternalHistoryError`

### 7. desktop 主进程装配

修改：

- `apps/desktop/main/index.ts`
- `apps/desktop/main/controlledPageManager.ts`
- `apps/desktop/main/authWindow.ts`
- `apps/desktop/main/providerHost.ts`

具体改动：

- `controlledPageManager.ensurePage` 扩展为支持 `preloadPath`
- `index.ts` 中 `resolveHistoryProvider('gemini-web')` 改为 lazy singleton：
  - `GeminiHistoryConfigLoader + GeminiHistoryPageBridge + GeminiDomHistoryProvider`
- `authWindow.ts` 为 `gemini-web` 增加登录地址：
  - `DEFAULT_GEMINI_HISTORY_PAGE_URL`
- Gemini 登录窗口标题固定为 `登录 Gemini`

默认行为：

- 继续复用 `persist:chatprism-gemini`
- 不在主进程里自动弹登录窗
- 登录成功后只刷新外部历史列表，不自动导入具体会话

### 8. desktop renderer 恢复交互

修改：

- `apps/desktop/src/App.vue`
- `packages/ui/src/views/ConversationWorkspaceView.vue`
- `packages/ui/src/views/NormalChatView.vue`

具体改动：

- `NormalChatView` 增加通用宿主恢复入口：
  - `hostRecoveryMessage?: string`
  - `hostRecoveryActionLabel?: string`
  - `hostRecoveryActionDisabled?: boolean`
  - `request-host-recovery`
- `ConversationWorkspaceView` 只做透传
- `App.vue` 统一处理恢复逻辑：
  - `requestProviderLogin(providerId: 'chatgpt-web' | 'gemini-web'): Promise<void>`
  - 当前处于 Gemini 外部历史且错误为 `AUTH_REQUIRED` 时，显示 `登录 Gemini`
  - `onProviderLoginWindowClosed('gemini-web')` 后，如果当前仍处于该来源，调用 `chatStore.loadExternalHistory('gemini-web')`
