# ChatPrizm 架构设计：基于文件树的作用域级 Agent 机制

## 1. 核心理念：上下文隔离与本地优先 (Local-First)
ChatPrizm 旨在构建一个多智能体协作（Multi-Agent）的知识空间。通过将 Agent 配置与物理文件树深度绑定，实现不同工作流（如代码开发、日常笔记、文档编写）的上下文隔离。
用户无需手动切换 AI 助手，系统会根据当前激活的文件节点，自动感知并切换对应的 Agent 身份与能力。所有配置遵循“配置即代码 (Config-as-Code)”理念，作为隐藏文本文件沉淀在本地目录中，支持随知识库无缝同步与版本控制。

## 2. 存储规范：`.agent.json`
Agent 的身份与能力定义通过标准的 JSON 格式，分布式地存储在知识库的文件夹中。
* **文件命名**：固定为 `.agent.json`。
* **核心字段规范**：
    * **基础信息**：定义 Agent 的名称 (Name) 与 职责描述 (Description)。
    * **核心指令**：核心设定与系统提示词 (Instructions / System Prompt)。
    * **能力组装**：
        * **工具 (Tools)**：定义该 Agent 允许调用的底层执行动作（如：读取文件、跨文件检索、执行脚本等）。
        * **技能 (Skills)**：定义可复用的动态 Prompt 注入片段或预置工作流。
    * **继承策略 (Inheritance)**：显式声明子文件夹 Agent 是“完全覆盖 (Override)”父级设定，还是与父级进行“深度合并 (Merge)”（如合并工具列表、叠加 Prompt）。

## 3. 寻址与继承解析算法 (最近父级原则)
系统采用类似“原型链/作用域链”的向上溯源算法，动态解析出用户当前上下文的完整 Agent 实体：
1. **确定起点**：若用户选中文件夹，则从此文件夹起算；若选中文件，则以其所在的父文件夹为起点。
2. **向上溯源查找**：检查当前层级是否存在 `.agent.json`。若无，则向上一级目录遍历，直至找到最近的配置文件。
3. **策略应用与级联**：
    * 若命中的配置文件策略为“合并 (Merge)”，解析器将继续向上查找更高级别的配置，并将两者的能力与指令进行堆叠。
    * 若策略为“完全覆盖 (Override)”，溯源立即终止，以当前文件配置为最终形态。
4. **全局兜底 (Fallback)**：若遍历至根目录（Root）仍未发现任何配置，系统分配一个具备基础读写能力与通用 Prompt 的全局默认 Agent。

## 4. 架构解耦：定义 (Context) 与执行 (LLM Adapter) 分离
系统在架构上将“Agent 具备什么能力”与“如何驱动大模型执行能力”进行了严格解耦，以保证未来可以灵活接入各类大模型。

* **上下文提供层 (ContextProvider)**：
  专注于本地文件系统的 I/O 操作与继承算法。负责扫描、读取并最终拼装出一个与平台无关的、标准化的 `AgentConfig` 实体。
* **模型适配执行层 (LLM Provider / Adapter)**：
  接收标准化配置，并根据具体 LLM 接口的特性，决定执行工具 (Function Calling) 的策略：
  * **原生 API 接入 (如官方 API)**：直接将配置转化为请求参数中的 `tools` 或 `functions` 字段。
  * **非原生接入 (如网页端模拟/逆向调用)**：采用 Prompt Engineering（如 ReAct 模式），将工具定义硬编码到系统指令中发给大模型；在接收流式输出时，通过前端正则引擎拦截 (Soft Function Calling) 特定格式的 JSON 命令，在本地暗中执行工具后，将结果拼接回传给大模型，实现 Agent 闭环。

## 5. 性能优化 (延期规划)
* **路径缓存树**：为避免在深层文件树中高频点击带来的冗余磁盘读取，后续将在内存中建立 `目录路径 -> Agent配置` 的映射缓存机制。仅在监听到本地 `.agent.json` 发生物理变动时，才使对应层级的缓存失效。
