ChatPrizm 文件上传与多模态交互演进方案
1. 目标概述
在 ChatPrizm 现有的多端联动架构基础上，平滑引入文件与图片上传功能，以增强“多模态印证”的场景价值。同时在 UI/UX 上全面向 ChatGPT Web 版的暗色主题与极致简约风格看齐，剥离多余视觉干扰，打造沉浸式的个人知识管理（PKM）与高效对话体验。

2. 核心架构升级 (packages/core)
为了保持分层架构的纯粹性，需对现有的核心抽象进行扩展，重点解决多模态数据流转与多模型特殊标识的兼容问题。

2.1 统一模型接口扩展 (IModelProvider)
支持多模态输入：扩展 sendMessage 方法，支持接收附件元数据数组（如 attachments: { type, base64Data, name }[]）。

容量策略：现阶段暂不支持超过 10MB 的大文件分片上传。Gemini 等模型统一采用 Base64 Inline Data 模式进行传输，简化文件生命周期的状态管理。

2.2 响应解析流水线 (Response Parsing Pipeline)
为了解决不同大模型（如 ChatGPT）返回特殊标识（如 cite、image_group）导致前端渲染混乱的问题，引入中间件解析机制：

Provider 级预处理：在具体的 Provider（如 ChatGPTWebProvider）内部维护一套专属的正则表达式或流式字符替换规则。

标准化输出：Provider 在接收到原始流式数据后，将其特有的标识实时转换或清洗为统一的、UI 层可识别的 AST（抽象语法树）节点或标准 Markdown 扩展语法。

UI 纯粹渲染：packages/ui 层只负责渲染标准化的格式，完全与底层模型的私有标识解耦。

2.3 会话数据抽象更新 (Conversation)
在 Message 数据模型中增加 attachments 属性，用于持久化存储该条消息携带的文件元数据（如缩略图 Base64、文件名与类型），确保历史记录恢复时能够无缝展示多模态上下文。

3. UI/UX 设计规范 (packages/ui)
严格遵循 ChatGPT Web 版的视觉习惯，以“暗色沉浸”和“降噪聚焦”为核心设计原则。

3.1 全局暗色主题 (Dark Theme)
色彩基调：采用深灰至近黑的色阶（如参考 ChatGPT 的 #212121 核心背景色），文字采用高对比度的浅灰/纯白，降低长时间使用的视觉疲劳。

代码块适配：针对代码高亮采用兼容暗色模式的专属主题（如 One Dark），并提供深色的“一键复制”操作条。

3.2 极简对话流 (Minimalist Thread)
无边框布局：彻底取消传统的聊天气泡边框。用户消息和 AI 消息通过纯粹的排版与细微的背景色差区分，文字内容左对齐或居中，限制在最大阅读宽度（约 800px）内。

模型标识与静默操作：AI 消息顶部仅保留极小尺寸的 Provider Logo。鼠标悬停时，才以极淡的图标显示“复制”、“重试”等操作按钮，平时保持视界纯净。

特殊内容优雅渲染：

引用 (cite)：渲染为原生的上标数字 [1]，鼠标悬停时弹出暗色半透明提示框显示来源。

图片组 (image_group)：渲染为现代化的多图宫格，支持点击唤出全屏暗色遮罩进行大图预览。

3.3 多模态输入区 (Input Area)
交互入口：输入框左侧（或内部左下角）提供精致的回形针或加号图标，点击唤出文件选择。

快捷输入：全局支持拖拽文件到输入区域，原生支持剪贴板图片直贴（Cmd+V / Ctrl+V）。

悬浮预览卡片：在输入文本框上方，以上传进度的形式展示带有圆角的缩略图卡片，并配有极简的关闭（删除）按钮。

3.4 扁平化历史记录 (Sleek Sidebar)
去分组设计：取消繁琐的时间轴分组，采用纯粹的扁平化时间倒序列表。

极致紧凑：历史标题单行显示，尾部优雅截断。侧边栏背景色与主对话区形成微妙的层级区分。

静默交互：默认不显示任何操作按钮，仅在鼠标悬停于当前会话项时，浮现“重命名”和“删除”的图标。

4. 扩展宿主适配 (apps/extension)
在浏览器插件环境中，由于前端页面无法直接传递二进制对象跨越进程，需优化跨端通信链路：

前端处理：UI 层将用户选择的文件/图片转换为 Base64 或 ArrayBuffer。

Proxy 转发：通过消息通信机制（Message Passing）将编码后的数据发往 Background 进程。

后台请求：Background 脚本中的真实 Provider 接收数据后，组装网络请求发往目标厂商（如模拟 ChatGPT Web 接口，或调用 Gemini API），解决跨域和权限限制。

5. 实施路线图
Phase 1: 核心扩展与解析准备

更新 Conversation 和 IModelProvider 的类型定义。

在 ChatGPTWebProvider 中实现流式拦截器，将 cite 和 image_group 等私有标识转换为标准占位符。

Phase 2: 暗色主题重构与多模态输入

确立全局 Dark Mode 调色板，重构对话流列表，移除气泡样式，引入标准 Markdown 渲染器。

实现输入框的拖拽、粘贴及附件缩略图预览功能。

将历史记录侧边栏改造为极简无分组扁平列表。

Phase 3: 宿主层与多模态接口打通

在 Extension Background 中实现 Base64 到 API 请求负载的组装与转换。

完成 Gemini API 的 Inline Data 模式接入；打通 ChatGPT Web 端的多模态消息发送与文件 ID 获取链路。

Phase 4: 体验打磨与跨端联调

测试多端联动，确保包含图片和附件的会话记录能正确通过 IStorageProvider 保存，并在跨端（Web/插件）恢复时渲染无误。

优化长对话与多图场景下的内存占用和滚动加载体验。
