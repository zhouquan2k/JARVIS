# 仓库开源英文化与 UI 国际化分阶段实现计划

## 摘要

* 复杂度评估：高。这个任务不是单纯翻译文档，而是要同时处理仓库对外入口、UI 用户面文案、运行时错误英文统一、以及正式 OpenSpec 文档的双语组织方式。

* 最终目标：

  * 仓库对外默认英文，适合 GitHub 开源展示和英文开发者阅读。

  * UI 完整用户面支持国际化，避免“文档英文、界面中文”的割裂状态。

  * 正式 OpenSpec 文档保留中英双语，并采用中英分文件；archive 暂缓处理。

* 范围确认：

  * 不处理现有 `my-README.md`。

  * 不翻译 `openspec/changes/archive/**`，只处理正式文档和活跃变更。

  * 面向用户展示的异常文本统一改为英文默认文案，暂不支持异常多语言。

## 分阶段实施

为降低一次性失败风险，实施拆分为 3 个阶段，每个阶段都有独立交付物与验收目标。

### Phase 1. 仓库公开入口英文化

目标：

* 先完成仓库对外默认英文的公开入口，不触碰运行时行为。

* 建立英文主文档与中文镜像的基础结构。

* 让 `docs/workspace.dsl` 成为对外架构主入口。

范围：

* 根文档与仓库元数据。

* 核心公开文档与架构图入口。

* 少量最关键 `docs/` 文档的英文主版本与中文镜像。

交付内容：

* `README.md`

* `README.zh-CN.md`

* `CONTRIBUTING.md`

* `CONTRIBUTING.zh-CN.md`

* `ARCHITECTURE.md`

* `ARCHITECTURE.zh-CN.md`

* `SECURITY.md`

* `CODE_OF_CONDUCT.md`

* `LICENSE`

* `package.json` 中的 `description` / `repository` / `homepage` / `bugs`

* `docs/workspace.dsl`

* `docs/zh/workspace.zh-CN.dsl`

* 核心 `docs/` 文档的 `English | 中文` 互链

本阶段不处理：

* UI i18n 基础设施

* 运行时异常链路改造

* OpenSpec 存量双语补齐

### Phase 2. UI 国际化基础设施与静态文案迁移

目标：

* 为 Web、Extension、Desktop 建立统一的 UI i18n 基础设施。

* 迁移主要静态用户可见文案。

* 不处理异常多语言，只处理静态界面文案。

范围：

* `packages/ui` i18n 模块、语言资源、切换与持久化。

* 三个宿主统一初始化语言环境。

* 共享组件、共享视图、以及 provider/model 的可见 label / description。

交付内容：

* `packages/ui` 新增 i18n 模块与语言资源

* `apps/web` / `apps/extension` / `apps/desktop` 接入语言初始化

* `packages/ui/src/components/**` 的主要静态文案迁移

* `packages/ui/src/views/**` 的主要静态文案迁移

* `packages/core/config.ts` 中用户可见 label / description 迁移

本阶段规则：

* 只迁移静态用户可见文案。

* `throw new Error(...)`、`currentError`、`analysisError` 等异常文本不进入 i18n 词条。

* 若异常文本会直接显示到界面，本阶段只要求它在后续阶段中改成英文默认文案。

### Phase 3. 异常英文统一与 OpenSpec 双语规范补齐

目标：

* 收口剩余高风险项：面向用户的异常文本英文统一、OpenSpec 双语规范化、维护规则补齐。

* 将最分散、最容易返工的部分独立处理，避免阻塞前两个阶段。

范围：

* UI 会直接显示的异常文本统一改英文。

* 保留已有错误码链路，但不做异常多语言。

* 正式 OpenSpec 文档按双语分文件补齐。

* `.github` 模板与贡献规范收口。

交付内容：

* 用户可见异常文本由中文改为英文默认文案

* 正式 OpenSpec 双语分文件规范落地

* `.github` issue / PR 模板英文优先

* `CONTRIBUTING.md` 中补充文案与双语文档规则

本阶段规则：

* 优先复用已有错误码，如 `AUTH_REQUIRED`、`DETAIL_NOT_FOUND`、`SELECTOR_MISMATCH`

* 未错误码化的路径，直接改英文默认消息，不新增异常多语言资源

* archive 继续不处理

* 内部日志不要求双语。

## 约束与假设

* `my-README.md` 保持不动，不纳入本轮治理。

* 英文是对外默认语言，中文继续保留。

* UI 国际化首轮覆盖完整用户面，不覆盖内部日志。

* 异常文本暂不支持多语言，只统一为英文默认文案。

* OpenSpec archive 暂缓，正式 specs 与活跃 change 必须双语。

* 正式 OpenSpec 双语采用分文件，而不是同页双语。

* 建议实施顺序：

  1. Phase 1：开源入口与文档规范
  2. Phase 2：UI i18n 基础设施与静态文案迁移
  3. Phase 3：异常英文统一、OpenSpec 双语化与规则补齐
