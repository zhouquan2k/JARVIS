# ChatPrizm: “Obsidian + AI” 知识库融合功能开发计划

## 1. 核心架构与 UI 布局
采用经典的三栏式可拖拽布局，实现类似 Obsidian 和 VS Code 的无缝工作流。
* **左侧面板 (20%)**：文件树 (File Explorer)，负责文件层级展示与切换。
* **中间面板 (50%)**：主编辑区 (Editor)，提供沉浸式 Markdown 富文本编辑体验。
* **右侧面板 (30%)**：AI 聊天窗 (Chat Interface，已实现)，负责与大模型交互。
* **布局机制**：使用可拖拽分割面板实现平滑的边界调整。

## 2. 前端技术栈选型 (Vue 3 生态)
充分利用 Vue 3 的 Composition API 和细粒度响应式优势，快速构建高性能基础底座。
* **基础布局组件**：使用 Splitpanes (极轻量、原生支持 Vue 3)。
* **左侧文件树**：选用支持虚拟滚动和复杂拖拽的 Vue 3 树形组件，或复用现有的 UI 库 Tree 组件。
* **中间核心编辑器**：采用 Tiptap。其无头 (Headless) 架构和底层基于 ProseMirror 的特性，将状态与 UI 解耦，完美契合 Obsidian 式的高度定制化需求。
* **状态管理纽带**：使用 Pinia 替代深层组件传参，实现左侧文件树与中间编辑器的状态全局集中同步。

## 3. 跨平台上下文与文件系统架构 (核心设计)

采用依赖倒置原则，通过抽象的 `ContextProvider` 接口将核心状态管理、AI 交互逻辑与底层的特定平台环境彻底解耦。

* **统一接口抽象 (ContextProvider)**：定义一套标准的异步文件操作规范，涵盖初始化权限、读取目录树、读取单文件内容、写入/更新文件、创建节点，以及供 RAG 使用的全文检索功能。
* **多平台适配实现**：
  * **Web App (现代浏览器)**：基于 File System Access API 实现，请求用户授权直接读写本地文件夹。
  * **Desktop App (Tauri / Electron)**：调用操作系统原生文件系统 API 实现。
  * **Browser Extension**：利用浏览器扩展专属的 Storage API 实现。
  * **Web 兼容模式**：针对不支持直接访问本地文件的环境，降级使用 IndexedDB 存储。
* **动态依赖注入**：全局状态 (Pinia Store) 仅依赖于抽象接口。应用在初始化时，根据当前运行环境自动嗅探并注入对应的具体 Provider 实例。

## 4. AI 读写链路与状态流转
建立底层抽象文件系统与大模型上下文的桥梁，让 AI 获得操作个人知识库的能力，并确保高频编辑的极致流畅。

* **大模型工具注册 (Function Calling)**：向大模型暴露基于 `ContextProvider` 封装的工具，允许 AI 主动读取文件补充上下文、直接覆写激活文件、在文档末尾追加内容，以及跨文件检索。
* **内存虚拟文件系统**：通过 Pinia 维护内存级别的状态，作为 UI、AI 与物理存储之间的缓冲层，避免频繁的磁盘 I/O。
* **无缝联动闭环**：
  1. 用户在左侧树切换文件，触发 Pinia 状态更新。
  2. 编辑器监听到状态变化，无缝切换视图内容，不销毁编辑器实例。
  3. 用户或 AI 在编辑器中修改内容，通过防抖机制更新内存状态，随后由注入的 Provider 执行异步物理落盘。
