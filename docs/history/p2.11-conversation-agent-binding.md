# 对话记录手动绑定 Agent 的实现计划

## 摘要

- 复杂度评估：中等。核心难点不是存储，而是把“手动改绑”的入口、候选 Agent 的读取、会话持久化以及 Agent 列表联动这条链路串起来，同时不破坏现有自动绑定逻辑。
- 最终行为：
  - 在普通对话工作台左侧本地历史项上，用户可以把一条现有会话手动绑定到某个 Agent。
  - 绑定、改绑、解绑都直接修改 `Conversation.agentKey`，并立即反映到知识工作区里的 Agent 会话列表。
  - 这个手动绑定只影响会话在 Agent 列表中的归属，不自动改变普通聊天页后续发送时的执行 Agent。

## 关键改动

### 1. 在本地历史项上增加 Agent 绑定入口

在 [packages/ui/src/components/ConversationSidebar.vue](/Users/quanzhou/Workspace/JARVIS/packages/ui/src/components/ConversationSidebar.vue) 的每条本地会话记录上增加一个 `绑定 Agent` 操作入口。

交互约定：

- 入口只作用于本地会话，不作用于外部历史。
- 点击后展开当前记录下方的行内选择面板，而不是新增全局弹窗。
- 面板内需要提供三类选项：
  - `不绑定`
  - 默认根作用域 Agent
  - 当前工作区 `agentConfigs` 中解析到的 scoped agents
- 绑定按钮和现有星标、删除保持同级，但二级面板同一时刻只允许展开一种操作态。

### 2. 在普通对话工作台装配层懒加载 Agent 候选项

在 [packages/ui/src/views/ConversationWorkspaceView.vue](/Users/quanzhou/Workspace/JARVIS/packages/ui/src/views/ConversationWorkspaceView.vue) 中接入 `contextProvider`，由装配层负责拉取 Agent 候选项并下发给侧边栏。

建议新增能力：

- `async function ensureAgentBindingOptionsLoaded(): Promise<void>`
- `async function onBindLocalAgent(payload: { conversationId: string; agentKey: string | null }): Promise<void>`

数据流约定：

- 只有在用户首次打开绑定面板时才调用 `contextProvider.initializeAccess()` 和 `contextProvider.getContext()`。
- 从 `contextProvider.getContext().agentConfigs` 构造可选 Agent 列表。
- 如果加载失败，只在绑定面板内显示错误，不影响普通聊天工作台的其他操作。

宿主侧需要继续把现有 `contextProvider` 透传进来：

- [apps/web/src/App.vue](/Users/quanzhou/Workspace/JARVIS/apps/web/src/App.vue)
- [apps/extension/src/App.vue](/Users/quanzhou/Workspace/JARVIS/apps/extension/src/App.vue)
- [apps/desktop/src/App.vue](/Users/quanzhou/Workspace/JARVIS/apps/desktop/src/App.vue)

### 3. 在 chat store 中新增显式手动绑定动作

在 [packages/ui/src/store/chat.ts](/Users/quanzhou/Workspace/JARVIS/packages/ui/src/store/chat.ts) 中新增：

- `async bindConversationToAgent(id: string, agentKey: string | null): Promise<void>`

实现约束：

- 该动作允许覆盖已有 `conversation.agentKey`，区别于当前只做首次自动补齐的 `applyConversationAgentKey(...)`。
- 绑定时继续复用现有的 `resolveConversationAgentKey(agentKey: string | null): string | undefined` 做规范化。
- 绑定完成后需要：
  - 持久化到 `storageProvider`
  - 刷新本地会话列表
  - 同步更新 `currentConversation`

这里不改动 `sendDraft()` 的执行语义。也就是说，手动绑定完成后，这条会话在 Agent 相关列表里会归到对应 Agent，但普通聊天页继续发送时仍然以当前聊天上下文和工作区状态为准。

### 4. 继续复用现有 Agent 聚合规则

知识工作区里现有的 Agent 列表已经是围绕 `conversation.agentKey` 做聚合的，因此这次不需要新增第二套归类字段。

会被直接受益的地方：

- [packages/ui/src/components/AgentPane.vue](/Users/quanzhou/Workspace/JARVIS/packages/ui/src/components/AgentPane.vue)
- [packages/ui/src/components/AgentView.vue](/Users/quanzhou/Workspace/JARVIS/packages/ui/src/components/AgentView.vue)

行为约定：

- 只要 `conversation.agentKey` 指向当前 Agent，它就应立即出现在该 Agent 的本地会话列表中。
- 解绑后，这条会话应立即从相关 Agent 列表中消失。
- 不额外区分“自动绑定”和“手动绑定”，列表逻辑保持单一标准。

## 测试计划

### 1. Store 测试

- 手动绑定一条本地会话后，`conversation.agentKey` 会被正确写入并持久化。
- 改绑时会覆盖旧的 `agentKey`。
- 解绑时会清空 `agentKey`。
- 绑定后 `getConversationsByAgent(...)` 的结果会立即变化。

### 2. 组件测试

- 本地历史项能显示 `绑定 Agent` 入口。
- 首次展开绑定面板时会触发候选 Agent 加载。
- 选中某个 Agent 后会发出正确的绑定事件。
- 加载失败时只影响绑定面板，不影响会话切换、星标和删除。

### 3. 端到端测试

- 在普通对话页创建一条本地会话。
- 把这条会话手动绑定到某个 Agent。
- 切到知识工作区后，打开对应 Agent 目录或右侧 Agent pane，能看到这条会话出现在 Agent 列表中。
- 解绑后，该会话从 Agent 列表消失。

## 约束与假设

- 本次不新增数据库列，也不改同步协议，继续复用现有 `Conversation.agentKey`。
- 本次只做“会话归类”层面的绑定，不让手动绑定自动切换普通聊天页后续发送的 Agent 执行上下文。
- 外部历史和对比会话不纳入这个功能。
- 候选 Agent 直接来自当前工作区 `contextProvider.getContext().agentConfigs`，不再维护第二份 Agent 列表来源。
