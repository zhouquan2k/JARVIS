# linkDir 挂载顶层目录实现计划

## 摘要

- 复杂度评估：中等偏高。核心难点不在 UI，而在把“外部目录挂载”为顶层目录后，仍然保持路径、Agent 继承、读写、搜索和节点操作的一致语义。
- 最终行为：
  - 根目录下的空目录如果在 `.agent.json` 里声明 `linkDir`，就会被当作一个顶层挂载入口。
  - 挂载进来的目录在知识工作区里使用虚拟路径展示，但实际读写、创建、删除、重命名和搜索都落到真实目标目录。
  - 挂载根目录本身只作为别名入口处理，重命名或删除只影响工作区中的入口，不直接改动真实目标目录。
- 本次只扩展本地文件系统知识上下文，不改 `IContextProvider` 公共契约。

## 关键改动

### 1. 扩展 `.agent.json` 解析，支持 `linkDir`

在 [packages/node/src/context/FileSystemContextProvider.ts](/Users/quanzhou/Workspace/JARVIS/packages/node/src/context/FileSystemContextProvider.ts) 中扩展 Agent 配置解析：

- 新增 `linkDir` 字段支持。
- `linkDir` 仅允许作为空目录的挂载声明使用。
- `linkDir` 解析以声明目录为基准，支持相对路径。
- 挂载目标必须存在且必须是目录。

### 2. 在上下文 provider 内构建挂载表

在 `FileSystemContextProvider` 内新增挂载发现与映射逻辑：

- 扫描根目录时识别顶层空目录挂载入口。
- 维护一张“虚拟路径 -> 真实路径”的映射表。
- `getContext()` 返回的 `ContextNode` 树继续使用虚拟路径。
- 挂载目录的 `agentKey`、`isAgentOwner` 和 `sourcePaths` 仍按虚拟路径语义计算。

### 3. 统一读写、节点操作和搜索路径解析

同一个 provider 里的这些方法都必须理解挂载语义：

- `readDocument(path: string): Promise<ContextDocument>`
- `writeDocument(input: WriteContextDocumentInput): Promise<void>`
- `createNode(input: CreateContextNodeInput): Promise<ContextNode>`
- `deleteNode(targetPath: string): Promise<void>`
- `renameNode(input: { path: string; name: string }): Promise<ContextNode>`
- `searchInScope(request: ContextSearchRequest): Promise<ContextSearchMatch[]>`

行为要求：

- 对挂载目录中的文件，返回和接收的路径都保持虚拟路径。
- 真正落盘时映射到挂载目标目录。
- 搜索结果不暴露真实物理路径。

### 4. 补齐上下文和工作区测试

需要补充的测试范围：

- `packages/node/src/context/FileSystemContextProvider.test.ts`
- `apps/server/tests/local-file-context-provider.test.ts`

重点覆盖：

- 挂载目录出现在顶层上下文。
- 挂载目录中的读写、创建、删除、重命名都能落到真实目标目录。
- 挂载根别名的删除和重命名只影响入口本身。
- 非法挂载声明会明确报错。

### 5. 新增 Playwright 真实链路用例

补充知识工作区的 e2e 场景，验证真实 UI 链路：

- 挂载目录会作为顶层目录出现在文件树里。
- 在挂载目录内打开、编辑、保存文件后，刷新或重新打开页面仍能看到真实目标目录中的更新。
- 对挂载根别名执行改名或删除时，真实目标目录保持不变。

## 测试计划

### 1. Provider 单测

- 根目录空目录声明 `linkDir` 时能被识别为挂载入口。
- 挂载目录中的文件读写仍能正确映射到真实目标目录。
- 挂载目录中新建节点时，返回给 UI 的路径和 `parentPath` 继续保持规范化后的虚拟路径。
- 挂载目录的搜索结果路径保持虚拟路径。
- 非法 `linkDir` 和非空挂载目录会报错。

边界条件说明：

- `linkDir` 必须是非空字符串；空字符串、只包含空白或非字符串值都属于非法声明。
- `linkDir` 相对路径总是以声明该配置的目录为基准解析，不以上下文根目录为基准。
- 解析后的挂载目标必须存在且必须是目录；指向不存在路径或普通文件时会显式报错。
- 根目录下的挂载入口必须保持“空目录 + .agent.json”，如果混入其他可见文件或子目录，会按非法挂载入口处理。
- 挂载声明解析失败时不会静默降级为普通空目录，避免 UI 和 Agent 作用域在不同宿主里出现不一致结果。

### 2. 服务端回归测试

- `LocalFileContextProvider` 的 HTTP 暴露层继续保持一致行为。
- 没有 `linkDir` 的旧工作区仍按原逻辑工作。

### 3. Playwright e2e

- 验证挂载目录在文件树中的展示。
- 验证挂载目录的编辑链路。
- 验证挂载根别名的重命名 / 删除语义。

## 约束与假设

- `linkDir` 只支持单目录挂载，不支持一个入口挂多个目录。
- 挂载入口仅限根目录下的空目录，避免本地文件和外部目录混合展示。
- 本次不新增独立挂载管理 UI。
- 真实路径只在 provider 内部使用，对外统一返回虚拟路径。
