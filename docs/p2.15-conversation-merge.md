# PRD：归档对话到当前 Q/A 文档

## 1. 功能概述

在用户点击“归档”按钮后，系统将当前对话内容按 Q/A 结构合并到当前打开的 Markdown 文档中。

该文档采用单文件双区结构：

* `Q` 区：沉淀用户输入的问题、背景、约束与补充信息

* `A` 区：沉淀 AI 输出的方案、结论、建议与结构化结果

系统以文档中的首个 Markdown 标准分割线作为 Q/A 分界。归档时，用户输入归并到 `Q` 区；AI 输出在去重、整理后归并到 `A` 区。

## 2. 背景与目标

当前 JARVIS 已明确采用单文档 `Q/A` 协作模式，但对话内容如何稳定沉淀回文档仍缺少明确规则。若归档仅做原样追加，会带来以下问题：

* 对话内容冗余，文档快速膨胀

* 用户新增约束散落在聊天中，无法沉淀为后续 Agent 可复用的背景

* AI 多轮输出重复表达同一方案，导致 A 区混乱

本功能目标是建立一个可重复使用的“对话归档 -> 文档沉淀”机制，使聊天结果能持续回流为结构化知识，而不是一次性会话记录。

成功标准：

* 用户点击一次归档后，当前文档的 `Q` 与 `A` 区都能得到符合角色语义的更新

* `Q` 区能补充新背景、新限制、新问题，而不是混入 AI 方案

* `A` 区能合并 AI 有效结论，并避免明显重复

* 多次归档后，文档仍保持可读、可继续演进，而非变成聊天流水账

已确认补充：

* 单次归档范围为整个当前对话

* 同一对话不作为多次归档对象；归档完成后，用户应开始新的对话

## 3. 目标用户 / 相关角色

* 人类用户：在对话中提出问题、补充背景、修正约束，并触发归档

* Agent / AI：在对话中产出分析、建议、方案、结论，并作为 `A` 区归档来源

* 当前文档：归档目标对象，承载问题域内的结构化沉淀结果

## 4. 使用场景

核心场景：

* 用户围绕当前文档对应问题域与 Agent 多轮讨论后，点击“归档”将有效内容沉淀回文档

高频场景：

* 用户补充了新的限制条件，希望将这些约束写回 `Q` 区

* AI 在多轮讨论后形成更完整方案，希望将结论合并到 `A` 区

* 用户阶段性结束讨论，希望把本轮结论整理回文档而非保留在聊天线程中

特殊/异常场景：

* 当前文档不存在合法 Q/A 分隔结构

* 当前对话中只有用户发言或只有 AI 发言

* 当前对话与文档已有内容高度重复

* AI 在一轮中输出多个互相冲突的方案或已被后续轮次推翻的结论

## 5. 用户问题与需求定义

用户需要的不是“保存聊天记录”，而是“把聊天中的新增有效信息沉淀进当前文档”。

具体需求包括：

* 将用户输入中的新增背景、约束、问题点归并进 `Q` 区

* 将 AI 输出中的有效方案、建议、结论归并进 `A` 区

* 尽量去掉重复、废话、被后文重复表达的内容

* 归档结果仍然符合文档原有结构，便于后续继续编辑与继续问答

## 6. 功能范围

本次要做什么：

* 提供“归档当前对话到当前文档”的能力

* 基于文档中的首个 Markdown 标准分割线分割当前文档的 `Q` / `A` 两部分

* 将用户输入内容归并到 `Q` 部分

* 将 AI 输出内容做去重与结构化整理后归并到 `A` 部分

* 在正式写回前提供归档预览供用户确认

* 在归档后生成新的完整文档内容并写回当前文档

本次不做什么：

* 不将聊天全文逐条原样存档到文档

* 不在本期引入复杂的版本对比、逐条审批或细粒度人工挑选消息归档

* 不定义跨文档归档、归档到其他目录或自动归档策略

* 不解决“事实真伪校验”与“方案优劣自动裁决”

功能边界：

* 仅处理“当前对话 -> 当前文档”

* 仅处理单文档内首个 Markdown 标准分割线划分的 Q/A 结构

* 归档结果是“结构化摘要式合并”，不是聊天 transcript

## 7. 功能方案概述

用户点击归档后，系统读取当前文档内容，按首个 Markdown 标准分割线将文档切分为 `Q` 区和 `A` 区；若文档缺失分割线，则系统在文档末尾补齐分割线后再进行归档。系统随后抽取当前对话中的用户消息与 AI 消息：

* 用户消息：重写并提炼为更精炼的结构化问题定义、背景、限制、目标、澄清信息，并归并到 `Q` 区

* AI 消息：提炼新增方案、分析、建议、结论、执行要点，并在结构化整理中按段落级去重后归并到 `A` 区

系统先展示归档预览；用户确认后，系统输出新的完整 Markdown 文档并覆盖当前文档内容。

## 8. 功能流程

主流程：

1. 用户在当前对话点击“归档”
2. 系统读取当前活动文档内容
3. 系统查找文档中的首个 Markdown 标准分割线
4. 若分割线不存在，系统在文档末尾补齐分割线
5. 系统按首个分割线分出 `Q` 区与 `A` 区
6. 系统提取当前对话中的用户消息与 AI 消息
7. 系统将用户消息重写并归并进 `Q` 区
8. 系统将 AI 消息结构化整理并归并进 `A` 区
9. 系统生成归档预览
10. 用户确认归档
11. 系统生成新的完整文档内容并写回当前文档
12. 系统提示归档成功，并触发现有文档保存后的摘要更新流程

分支流程：

* 若当前对话仅有用户消息，则只更新 `Q` 区，`A` 区保持不变

* 若当前对话仅有 AI 消息，则只更新 `A` 区，`Q` 区保持不变

* 若对话内容与现有文档完全重复，则允许本次归档不产生文档改动，并给出“无新增内容”反馈

异常流程：

* 若当前无活动文档，则归档不可执行，并提示用户先打开文档

* 若归档预览生成失败，则归档失败，且不进入确认态

* 若文档写入失败，则归档失败，原文档保持不变，并给出失败反馈

回退或终止流程：

* 若用户在预览阶段取消归档确认，则终止本次归档且不写回文档

* 若系统在结构化归并阶段无法生成有效结果，则终止写回，避免产出破坏性内容

## 9. 功能规则说明

### 9.1 触发条件

* 用户点击 agentMode 右侧会话顶部工具条中的“归档”按钮

### 9.2 前置条件

* 存在当前活动对话

* 存在当前活动文档

* 当前活动文档为可写 Markdown 文档

### 9.3 输入与输出

输入：

* 当前文档原始内容

* 当前对话中的消息列表

输出：

* 一份新的完整 Markdown 文档内容

* 可选的归档结果反馈状态：成功 / 无新增内容 / 失败

### 9.4 Q/A 分割规则

已确认内容：

* 使用文档中的首个 Markdown 标准分割线作为 Q/A 分隔

* 分隔线之前视为 `Q` 区

* 分隔线之后视为 `A` 区

* 若文档中不存在分割线，则系统在文档末尾补齐一个标准分割线，再进行后续归档

合理假设：

* 若文档后续再次出现标准分割线，不作为新的 Q/A 顶层边界，仅视为正文内容或已有内容的一部分

规则细化：

* 这里的“Markdown 标准分割线”应兼容常见合法形式，如单独成行的 `***`、`---`、`___`

* 归档逻辑只识别首个满足 Markdown 规则的分割线

### 9.5 Q 区归并规则

已确认内容：

* 用户输入内容归并到 `Q` 区

合理假设：

* 归并对象应优先保留“问题、背景、目标、约束、补充事实、澄清信息”

* 纯礼貌语、闲聊、重复表达、无业务价值的口语化句子不应写入 `Q`

* 若用户后续消息否定前述条件，应优先保留最新有效约束

* `Q` 区允许系统重写为更精炼的结构化问题定义，而不是仅做原文追加

* 多轮用户输入互相冲突时，应按最新有效输入覆盖旧条件

### 9.6 A 区归并规则

已确认内容：

* AI 输出内容归并到 `A` 区

* 归并前需要去重与结构化

* 去重以结构化整理后的段落级去重为准

* AI 前后输出冲突时，应按最新有效结论覆盖旧结论

合理假设：

* 结构化后的 `A` 区应优先保留结论、方案要点、可执行建议、对比维度、风险点、待确认项

* 明显重复、仅换说法的内容应合并，不应重复保留

* 若 AI 多轮回答逐步完善同一方案，应合并为一份更完整表述，而不是逐轮追加

* `A` 区结构只要求整理清晰，不要求固定模板；可按当前文档上下文自由组织

### 9.7 状态变化 / 状态流转

* 初始态：当前对话进行中，当前文档未归档

* 归档中：系统正在读取文档、抽取对话、生成归并结果

* 归档成功：文档已写回新内容，并进入现有摘要刷新链路

* 无改动完成：归并后无新增有效内容，文档不变

* 归档失败：文档未改动，系统给出失败原因

### 9.8 权限控制

* 仅对当前可写文档开放归档

* 只允许用户主动点击触发，不自动执行

### 9.9 限制条件

* 仅归档当前对话，不回溯其他对话线程

* 仅作用于当前打开文档，不跨文档写入

* 单次归档范围固定为整个当前对话

* 默认不考虑同一对话多次归档场景；归档完成后，用户应开始新的对话

### 9.10 默认规则

* 默认归档整条当前对话，而非仅归档最近一轮

* 不引入“仅归档上次归档后的增量消息”规则

### 9.11 异常处理逻辑

* 无新增有效内容：允许返回成功但不改文档，或返回单独的“无新增内容”状态

* 模型归并结果不稳定或为空：不写回文档，避免污染

* 预览阶段取消确认：不写回文档，不触发保存链路

* 文档缺失分割线：系统自动补齐分割线后继续流程，而非直接报错

## 10. 页面 / 交互要求

* 在 agentMode 右侧会话顶部工具条提供明确的“归档”按钮，不再在输入区提供单独的归档入口

* 当存在当前对话且归档状态为“未归档”或“归档已过期”时，归档按钮应以高亮态显示，表示当前线程仍可归档

* 当当前对话已经完成归档时，归档按钮应显示为 disabled，避免重复触发

* 当不存在当前对话时，不显示归档按钮

* 当当前无文档或文档不可写时，按钮应禁用或点击后给出明确反馈

* 归档执行中应有进行中状态，避免重复点击

* 系统必须在正式写回前展示归档预览，至少让用户能看到将写入 `Q` 区和 `A` 区的结果

* 用户必须显式确认后，系统才可执行写回

* 归档完成后应反馈结果：

  * 成功：提示已归并到当前文档

  * 无新增内容：提示本次无新增可归档内容

  * 失败：提示失败原因

## 11. 数据与对象定义

核心对象：

* 当前文档

  * `path`

  * `content`

  * `canWrite`

* 当前对话

  * `conversationId`

  * `messages[]`

* 对话消息

  * `role`：`user` / `assistant`

  * `content`

  * `createdAt`

归档中间对象：

* `qSegment`：当前文档 Q 区内容

* `aSegment`：当前文档 A 区内容

* `userArchivePayload`：从用户消息提炼出的新增问题信息

* `assistantArchivePayload`：从 AI 消息提炼出的新增方案信息

* `archiveResultStatus`：`success` / `no_change` / `failed`

## 12. 依赖与约束

* 依赖当前工作区存在“当前活动文档”的概念

* 依赖当前对话消息可按角色读取

* 依赖现有文档写回能力

* 依赖现有“保存后刷新摘要”机制，保证归档后的文档可继续参与上下文检索

* 强依赖单文档 Q/A 结构约定；若该约定不成立，本功能不可正确执行

## 13. 风险与边界问题

* 若去重规则不清，A 区可能被过度压缩，丢失关键差异

* 若结构化改写力度过大，用户可能认为系统“篡改原意”

* 若用户归档后不开始新对话，仍在同一线程继续追问，会重新引入归档范围歧义

* 若用户与 AI 消息中包含相互矛盾内容，系统如何判定最终保留内容仍需规则约束

* 若当前文档已有强结构化格式，归并后的 A 区结构可能与原文风格冲突

* 若系统自动补齐分割线时未同步处理原文尾部格式，可能引入额外空行或版式扰动

## 14. 验收标准

1. 当存在可归档对话时，点击归档后系统必须先展示归档预览，且未经用户确认不得写回文档。
2. 当当前文档已包含 Markdown 标准分割线时，系统必须按首个分割线识别 `Q` / `A` 区并成功归档。
3. 当当前文档缺失 Markdown 标准分割线时，系统必须在文档末尾补齐分割线后继续归档，而不是直接报错。
4. 归档后，用户消息内容仅进入 `Q` 区，不得直接写入 `A` 区。
5. 归档后，AI 消息内容仅进入 `A` 区，不得直接写入 `Q` 区。
6. `Q` 区允许被重写为更精炼的结构化问题定义，且当新旧用户条件冲突时，最终文档必须以最新有效条件为准。
7. 若 AI 多轮输出存在明显重复表达，归并后的 `A` 区不应出现机械重复段落；去重口径以结构化后的段落级去重为准。
8. 若 AI 前后输出冲突，归并后的 `A` 区必须以最新有效结论为准。
9. 若本次对话没有新增有效内容，系统不得无意义改写整份文档。
10. 归档成功后，应继续进入现有文档摘要刷新流程。

## 15. 待确认事项

1. 归档确认完成后，系统是否应自动引导用户开启新对话，以避免继续复用已归档线程。
2. 归档预览的展示粒度应是“完整新文档预览”，还是“仅展示 Q/A 变化片段”。
3. 当文档中已存在多个合法 Markdown 分割线时，预览区是否需要明确标识“仅首个分割线参与 Q/A 分区”。
