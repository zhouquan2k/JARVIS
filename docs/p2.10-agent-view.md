# Agent 视图与 Agent 归属会话实现计划

## 摘要

- 复杂度评估：中等。UI 切换不复杂，核心在于补齐“会话直接绑定回答它的 Agent”这一持久化模型，并把知识工作区的目录选中态接到新的 Agent 视图上。
- 最终行为：
  - 只有当用户在知识工作区选中“当前目录下直接存在 `.agent.json`”的目录节点时，中间主面板显示 Agent 视图。
  - Agent 视图展示：Agent 基本信息、提示词、模型、该 Agent 下的 Markdown 文档列表、该 Agent 的本地对话记录列表。
  - 对话归属直接绑定到“实际回答该对话的 Agent”；普通聊天没有 Agent 绑定。
- 现有右侧 `AgentPane` 保留，继续承载 Agent 聊天；Agent 视图放在中间主面板。

## 关键改动

### 1. 扩展会话模型，记录 Agent 归属键

在 [packages/core/src/interfaces/Conversation.ts](/Users/quanzhou/Workspace/ChatPrism/packages/core/src/interfaces/Conversation.ts) 的 `Conversation` 增加可选字段：

```ts
agentKey?: string
```

设计约束：

- `agentKey` 作为会话归属主键；当前实现默认取“实际生效 Agent 的最终 `.agent.json` 路径”。
- 普通聊天会话不写 `agentKey`。
- 更新 `cloneConversation(conversation: Conversation): Conversation` 与 `normalizeConversation(conversation: Conversation): Conversation`，保证旧数据兼容。
- 不修改存储 provider 接口签名，继续使用现有 `saveConversation(chat: Conversation): Promise<void>`。

### 2. 在聊天发送链路里按“回答问题的 Agent”写入会话归属

在 [packages/ui/src/store/chat.ts](/Users/quanzhou/Workspace/ChatPrism/packages/ui/src/store/chat.ts) 增加辅助方法：

- `resolveConversationAgentKey(agent: ResolvedAgentConfig | null): string | undefined`
- `applyConversationAgentKey(conversation: Conversation, agent: ResolvedAgentConfig | null): void`
- `getConversationsByAgent(agentKey: string): Conversation[]`

规则：

- 只有通过 `activeAgentContext` 发送的 Agent 对话，才写入 `agentKey`。
- 新建普通聊天不预先绑定；首次实际由 Agent 回答后再落库绑定。
- 已绑定 Agent 的会话后续继续保留该绑定，不因当前目录切换而改绑到别的目录。
- Agent 会话列表只按 `agentKey` 过滤，不按目录是否仍被选中决定归属。

### 3. 在知识工作区增加“目录直绑 Agent”识别与中间面板切换

在 [packages/ui/src/store/documentWorkspace.ts](/Users/quanzhou/Workspace/ChatPrism/packages/ui/src/store/documentWorkspace.ts) 增加派生状态：

- `isDirectAgentDirectorySelected: boolean`
- `activeDirectAgentConfigPath: string | null`
- `activeAgentMarkdownDocuments: ContextNode[]`

新增辅助方法：

- `resolveDirectAgentSelection(path: string): void`
- `collectAgentMarkdownDocuments(scopePath: string): ContextNode[]`

判定规则固定为：

- 当前选中节点必须是目录。
- 该目录下必须直接存在 `.agent.json`。
- 仅满足以上条件时显示 Agent 视图。
- 文件选中、无 `.agent.json` 的目录、仅继承来的 Agent 均不显示 Agent 视图。

在 [packages/ui/src/views/DocumentWorkspaceView.vue](/Users/quanzhou/Workspace/ChatPrism/packages/ui/src/views/DocumentWorkspaceView.vue) 中：

- 中间 pane 在上述条件满足时渲染新的 Agent 视图组件。
- 否则继续渲染现有 `DocumentEditorPane`。
- 右侧继续保留现有 `AgentPane`。

### 4. 新增 Agent 视图组件

新建 `packages/ui/src/components/AgentDirectoryView.vue`。

建议 props：

- `agent: ResolvedAgentConfig | null`
- `agentKey: string | null`
- `documents: ContextNode[]`
- `conversations: Conversation[]`
- `selectedConversationId?: string | null`

展示内容：

- 基本信息：名称、描述、配置文件路径
- 提示词：`effectiveInstructions`
- 模型：`modelProviderName / modelName`
- 文档列表：当前 Agent 目录树下仅 `.md/.markdown`
- 对话记录：`agentKey === 当前 agentKey` 的本地会话

交互：

- 点击文档项调用 `documentStore.openNode(path)`
- 点击会话项调用 `chatStore.selectLocalConversation(id)`

## 测试计划

### 1. 存储与归一化测试

- 旧会话没有 `agentKey` 时仍可正常加载。
- 新会话写入 `agentKey` 后，`cloneConversation` / `normalizeConversation` 能完整保留。
- 普通聊天会话不会被误绑定 Agent。

### 2. Chat store 测试

- Agent 模式首次发送后，会话写入正确的 `agentKey`。
- 已绑定 Agent 的会话再次发送时不会因当前目录变化而重写绑定。
- `getConversationsByAgent(agentKey)` 只返回该 Agent 的本地会话。

### 3. Document workspace / 组件测试

- 选中“目录下直接存在 `.agent.json`”的目录时，中间 pane 渲染 Agent 视图。
- 选中文件、无 `.agent.json` 的目录、仅继承父目录 Agent 的目录时，不渲染 Agent 视图。
- Agent 视图的 Markdown 文档列表只包含 `.md/.markdown`。
- Agent 视图的会话列表只包含当前 Agent 绑定会话，普通聊天不出现。
- 点击文档、点击会话的跳转行为正确。

## 约束与假设

- 由于当前 Agent 配置结构没有显式 `id`，本次以“最终生效 `.agent.json` 路径”作为 `agentKey`。这是 Agent 身份键，不是目录筛选键。
- Agent 视图的显示条件严格基于“当前选中目录是否直接存在 `.agent.json`”；这只决定是否展示 Agent 视图，不决定会话归属。
- 外部历史预览不纳入 Agent 会话列表；Agent 视图只展示本地持久化会话。
- 本次不扩展 `.agent.json` schema，不新增显式 `agentId` 字段。
